# Link Platform v1 — Design

Date: 2026-10-08
Status: Approved in conversation; pending written-spec review

## 1. Goal

Bring tan to parity with the core link features of competing shorteners, on an
API and storage design that holds up under very high redirect and click volume.

### In scope

| #   | Feature                                                                                                  |
| --- | -------------------------------------------------------------------------------------------------------- |
| 1   | Edit a link (destination, code, expiry, and every field below)                                           |
| 2   | Aggregated analytics: time series, country, city, device, browser, OS, referrer, source, unique visitors |
| 3   | Date range and multi-value filters on analytics                                                          |
| 4   | Link title and description, search, filter list by creator                                               |
| 5   | Tags (many per link) and tag filter                                                                      |
| 6   | QR code generation (SVG/PNG, colors)                                                                     |
| 7   | QR scans vs. normal clicks                                                                               |
| 8   | Full UTM support (`utm_term`, `utm_content`, server-side UTM builder)                                    |
| 9   | `X-Robots-Tag: noindex` on redirects, plus a `robots.txt` that blocks only `/api/`                       |
| 10  | 301/302 choice per link                                                                                  |
| 11  | Viewer (read-only) organization role                                                                     |

### Out of scope

Password-protected links, link disabling/pausing, negative analytics filters,
CSV export, custom domains, durable click queue (Redis Streams).

### Decisions made during design

- **Analytics storage:** Postgres. Raw clicks go into monthly partitions, and
  dashboards read hourly rollup tables. ClickHouse can replace the analytics
  repository later if needed.
- **API shape:** a new `/api/v1`, grouped by resource, with links addressed by
  an immutable public ID. `/api/urls` is removed (no production clients).
- **Password links:** dropped from this round.

### Assumptions

- Backend only. The frontend remains `docs/frontend-spec.md`.
- Postgres 16 and Redis 7 remain the only datastores. Redis stays optional:
  everything degrades to single-instance behaviour without it.
- Uncommitted work-in-progress in the tree is kept and built on: owner/admin
  link deletion, `getMemberRoles`, and the `EMAIL_FROM` parsing.

## 2. API conventions

- **Base path:** `/api/v1`. Auth is unchanged: a Better Auth session via
  `Authorization: Bearer <token>`. Every route is scoped to the session's
  active organization (`requireAuth`, then `requireOrganization`, then
  `requirePermission`).
- **Resource identity:** a link's `id` is `link_` plus 24 random base62
  characters, stored in a unique `public_id` column. It is generated by the
  existing CSPRNG helper (`generateCode`, generalised to take a length). The
  internal `bigserial` id never leaves the server. `code` is an ordinary
  editable field.
- **Tag identity:** `tag_` plus 24 base62 characters.
- **Pagination:** cursor-based keyset. `?limit=1..100` (default 20) and
  `&cursor=`.
  - The response is `{ data: [...], nextCursor: string | null }`.
  - The cursor is opaque: base64url of the JSON
    `{ k: sortKeyValue, id: publicId }`. The tiebreaker is the public ID, so
    the internal id never appears in a cursor.
  - Keyset order is `(created_at, public_id)` or `(click_count, public_id)`,
    depending on `sort`.
  - `urls.created_at` is narrowed to `timestamptz(3)` (millisecond
    precision), so a cursor value round-trips through a JS `Date` exactly.
  - No `total` is returned; counting every row doesn't scale.
- **Status codes:**
  - Create returns `201` with a `Location` header.
  - Read and PATCH return `200`; DELETE returns `204`.
  - Errors: validation `400`, unauthenticated `401`, wrong role `403`,
    missing or in another org `404`, alias taken `409`, expired link (on
    redirect) `410`, rate-limited `429`.
- **Errors:** the unchanged envelope `{ error: { code, message } }`.
- **PATCH semantics:** JSON merge. An omitted field is unchanged, and `null`
  clears a nullable field (`title`, `description`, `expiresAt`).
- **Validation:** Zod at the boundary via the existing `validateBody` and
  `validateQuery`.
- **Rate limits:**
  - Existing limiters stay: `api` for management, `redirect` for public
    redirects, `auth` for auth endpoints.
  - They're mounted per route group in `src/routes/v1.ts`.
  - QR requests share the `api` limiter.

## 3. Routes

```
/api/v1
  POST   /links                 create
  GET    /links                 list   ?q &tagIds &userId &sort=createdAt|clicks &order=asc|desc &cursor &limit
  GET    /links/:id             read (includes totals: clicks, qrScans)
  PATCH  /links/:id             update
  DELETE /links/:id             soft-delete
  GET    /links/:id/qr          QR image  ?format=svg|png &size=128..2048 &fg &bg &margin=0..10 &ecc=L|M|Q|H
  POST   /tags                  create
  GET    /tags                  list (all of the org's tags, ≤500, no pagination)
  PATCH  /tags/:id              rename / recolor
  DELETE /tags/:id              delete (unlinks from links)
  GET    /analytics             aggregate query (§7)

GET /robots.txt                 "User-agent: *\nDisallow: /api/" (short links stay crawlable so preview bots work and see noindex)
GET /:code[/:channel]           public redirect
```

### Link resource (response)

```json
{
  "id": "link_…",
  "code": "abc1234",
  "shortUrl": "https://tan.sh/abc1234",
  "url": "https://example.com/p?utm_source=x",
  "utm": { "source": "x", "medium": null, "campaign": null, "term": null, "content": null },
  "title": "Launch post",
  "description": null,
  "redirectType": 302,
  "expiresAt": null,
  "tags": [{ "id": "tag_…", "name": "launch", "color": "blue" }],
  "shareUrls": { "instagram": "https://tan.sh/abc1234/ig", "…": "…" },
  "clicks": 1234,
  "createdBy": "user id",
  "createdAt": "…",
  "updatedAt": "…"
}
```

`GET /links/:id` adds `"qrScans": n`, which is the rollup sum where
`source = 'qr'`.

### Create / update body

| Field          | Create         | PATCH    | Rules                                                                                     |
| -------------- | -------------- | -------- | ----------------------------------------------------------------------------------------- |
| `url`          | required       | optional | existing rules: http(s), ≤2048, no credentials, not self, Safe Browsing                   |
| `code`         | optional       | optional | 3–32 `[A-Za-z0-9_-]`, not reserved, unique (409)                                          |
| `title`        | optional       | nullable | ≤200                                                                                      |
| `description`  | optional       | nullable | ≤1000                                                                                     |
| `expiresAt`    | optional       | nullable | must be in the future                                                                     |
| `redirectType` | optional (302) | optional | `301` or `302`                                                                            |
| `utm`          | optional       | optional | object of `source, medium, campaign, term, content`, each ≤200, `null` removes that param |
| `tagIds`       | optional       | optional | ≤10, all must belong to the org; PATCH replaces the set                                   |

`customAlias` is renamed to `code`. On PATCH, when `utm` and `url` are both
given, the UTM params are merged onto the new `url`.

**UTM model:**

- The destination URL is the single source of truth.
- `utm` is applied by setting or deleting `utm_*` params on the URL with
  `URLSearchParams`. Other params and their order are preserved.
- The response's `utm` object is parsed back out of the stored URL.

## 4. Permissions

Better Auth's `organization` plugin gets a custom access control. In
`src/modules/auth/permissions.ts`:

| Resource.action                     | owner | admin | member   | viewer |
| ----------------------------------- | ----- | ----- | -------- | ------ |
| link.read, tag.read, analytics.read | ✓     | ✓     | ✓        | ✓      |
| link.create                         | ✓     | ✓     | ✓        | ✗      |
| link.update, link.delete            | any   | any   | own only | ✗      |
| tag.create, tag.update, tag.delete  | ✓     | ✓     | ✓        | ✗      |

- **Guard:** `requirePermission(resource, action)` is Express middleware that
  checks the roles already loaded by `requireOrganization`. No extra DB call.
- **Ownership rule:** "own only" is enforced in the service. It generalises
  the existing `isOrgAdmin` check in `remove`.
- **Inviting viewers:** Better Auth's invite endpoint accepts
  `role: "viewer"`.

## 5. Redirect path

Order in `app.ts`: health routes, `/robots.txt`, `/api/auth/*`, `/api/v1`,
then `/:code/:channel?`.

1. Reject strings that can't be a code (existing `CODE_PATTERN` and reserved
   set) before any I/O.
2. **Lookup:**

- Check the L1 in-process LRU first (existing `LinkCache`, 30s TTL, 50k
  entries).
- Then the L2 Redis key `link:{code}`, JSON, 1h TTL.
- Then Postgres. Each hit fills the levels above it.
- Misses are cached as a tombstone (L1 + L2, 30s) so code scanning doesn't
  reach the DB.
- Cached value: `{ id, url, expiresAt, redirectType }` or `{ missing: true }`.

3. An expired link returns `410`.
4. `clickRecorder.enqueue(link.id, meta)`, unchanged and non-blocking.
5. Redirect with `link.redirectType`.

- **302:** `Cache-Control: private, max-age=0`.
- **301:** `Cache-Control: private, max-age=3600`. The cap stops browsers
  caching a permanent redirect forever. The docs warn that 301 under-counts
  repeat visits.

6. Every redirect, 404 and 410 response sets `X-Robots-Tag: noindex, nofollow`.

**Invalidation:**

- After a link update or delete commits, the service calls
  `linkCache.invalidate(codes)` for the old code, plus the new code if it
  changed. This step:
  - deletes the L1 entries,
  - `DEL`s the L2 keys,
  - and `PUBLISH`es the codes on `link:invalidate`.
- Every instance holds one subscriber connection (`redis.duplicate()`) and
  deletes those codes from its own L1.
- Without Redis, it falls back to L1 only with a 30s TTL (today's behaviour).
- **Redis failures** fail open: lookups fall through to Postgres, and
  invalidation errors are logged. A failed L2 `DEL` is bounded by the 1h TTL,
  which is an accepted limit and gets a `ponytail:` comment.

**Code changes:** the old code is freed immediately. Links already shared
with it stop resolving. This is documented in the API docs.

## 6. Data model

All changes ship as drizzle migrations. Partitioning and `pg_trgm` are
hand-written SQL in the migration.

### `urls` (extended)

| Column          | Type                               | Notes                        |
| --------------- | ---------------------------------- | ---------------------------- |
| `public_id`     | text unique not null               | backfilled for existing rows |
| `title`         | text null                          |                              |
| `description`   | text null                          |                              |
| `redirect_type` | smallint not null default 302      | check in (301, 302)          |
| `updated_at`    | timestamptz not null default now() |                              |

**Indexes:**

- `(organization_id, created_at, public_id)`, replacing the current org index
- `(organization_id, click_count, public_id)`
- `(organization_id, user_id, created_at)`
- GIN `pg_trgm` on `code`, `title` and `original_url`, for `q` search with
  `ILIKE`

### `tags`, `link_tags`

```
tags(id text pk 'tag_…', organization_id fk cascade, name text ≤50, color text,
     created_at)   unique (organization_id, lower(name))
link_tags(url_id fk cascade, tag_id fk cascade, pk (url_id, tag_id))  index (tag_id)
```

- Colors are a fixed palette:
  `gray|red|orange|yellow|green|blue|purple|pink`.
- Limits are enforced in the service: 10 tags per link and 500 per org.

### `clicks` (repartitioned)

- `PARTITION BY RANGE (created_at)`, with primary key `(id, created_at)`.
- Index `(url_id, created_at)`.
- New columns: `utm_term`, `utm_content`, and `visitor_hash`.
- **Migration:** create `clicks_new` partitioned, create partitions covering
  the existing data's month range, copy the rows, swap the names, and drop the
  old table.
- **Partition upkeep:** `ensureClickPartitions()` runs
  `CREATE TABLE IF NOT EXISTS clicks_YYYY_MM PARTITION OF …` for the current
  month and the next 2. It runs in `db:migrate`, at startup, and every 24h.
  It's idempotent, so concurrent instances are safe.
- **Retention:** when `CLICK_RETENTION_DAYS` is set, partitions entirely older
  than the cutoff are `DROP`ped. This replaces `deleteClicksBefore`.

### `click_rollups`

```
organization_id text, url_id bigint, bucket timestamptz (hour, UTC),
country text, city text, device text, browser text, os text,
referer_host text, source text,
clicks bigint, uniques bigint
unique (url_id, bucket, country, city, device, browser, os, referer_host, source) NULLS NOT DISTINCT
index (organization_id, bucket)
index (url_id, bucket)
```

- `browser` and `os` are stored without versions ("Chrome", not "Chrome 129").
- `referer_host` is the lowercase hostname without `www.`, or null when the
  click was direct.
- Missing dimension values are stored as `NULL`. `NULLS NOT DISTINCT`
  (Postgres 15+) keeps them in a single upsert row.

### `visitor_days`

```
url_id bigint, day date, visitor_hash bytea(16), pk (url_id, day, visitor_hash)
```

- Rows older than yesterday are pruned every 24h by the partition job.

## 7. Analytics

### Write path

`ClickRecorder.flush` runs one transaction per batch:

1. Bulk insert the raw clicks.
2. `INSERT … ON CONFLICT DO NOTHING RETURNING` into `visitor_days`. The
   returned rows are the first visit of each visitor today.
3. Aggregate the batch in memory by rollup key, computing `clicks` and
   `uniques`, where uniques are the first-visit rows from step 2.
4. One multi-row upsert into `click_rollups`:
   `ON CONFLICT … DO UPDATE SET clicks = click_rollups.clicks + excluded.clicks, uniques = …`.
5. The existing `click_count` delta update.

**Visitor hash:**

- First 16 bytes of `HMAC-SHA256(BETTER_AUTH_SECRET, utcDay | fullIp | userAgent | urlId)`.
- Computed in `buildClickData` before IP anonymisation.
- It's per day and per link, so visitors can't be linked across days or
  links, and no raw IP is stored.

### Query: `GET /api/v1/analytics`

| Param                                                 | Values                                                                                                                    |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `groupBy`                                             | `timeseries` (default), `countries`, `cities`, `devices`, `browsers`, `os`, `referers`, `sources`                         |
| `start`, `end`                                        | ISO datetimes; default last 30 days; max span 2 years                                                                     |
| `interval`                                            | `hour`, `day`, `month`; default is hour up to 2 days, day up to 90, month beyond. Hour is rejected for spans over 31 days |
| `timezone`                                            | IANA name, default `UTC`; validated with `Intl.DateTimeFormat`                                                            |
| `linkId`, `tagId`                                     | comma lists; tag uses an `EXISTS` on `link_tags`                                                                          |
| `country, city, device, browser, os, referer, source` | comma lists → `IN (…)`                                                                                                    |

- **Security:** dimensions come from a fixed whitelist that maps each param to
  a column. Every value is a bound parameter. `organization_id = $org` is
  always applied.
- **Time series:**
  `date_trunc($interval, bucket AT TIME ZONE $tz)`, grouped and ordered by
  that, with gaps filled by `generate_series`.
  - Response: `{ data: [{ start, clicks, uniques }] }`.
- **Breakdowns:** `GROUP BY dim ORDER BY clicks DESC LIMIT 100`.
  - Response: `{ data: [{ value, clicks, uniques }] }`.
- **Uniques:** visitor-days, meaning a visitor is counted once per link per
  day. Documented as such.

**Backfill:** the migration fills `click_rollups` from the existing raw
clicks. Historical `uniques` are estimated as
`count(DISTINCT (ip, browser, os))` per link, day and dimension set, credited
to the first hour of the day.

## 8. QR codes

- **Library:** `qrcode`, the one new dependency.
- **Encoded content:** `{shortUrl}/qr`, so scans are attributed via the
  existing `qr` channel (`source = 'qr'`, `method = 'channel'`).
- **Parameters:**
  - `format`: `svg` (default) or `png`
  - `size`: 128–2048 px, default 512
  - `fg` and `bg`: hex `#rrggbb`, default black on white
  - `margin`: 0–10, default 2
  - `ecc`: `L`, `M`, `Q` or `H`, default `M`
- **Contrast:** colors whose contrast ratio is below 3:1 get a 400.
- **Caching:** `Cache-Control: private, max-age=86400`, plus an `ETag` from
  hashing the code and params; `If-None-Match` gets a `304`. Generated per
  request, with no storage.
- **Download name:** `Content-Disposition: inline; filename="<code>.svg|png"`.

## 10. Known limits

Each limit is marked in code with a `ponytail:` comment.

- **In-memory click buffer:** a crash loses up to about 1s of clicks. The
  upgrade is Redis Streams.
- **Rollup row count:** can approach raw volume for links whose traffic is
  spread across very many cities or referrers. The upgrade is dropping `city`
  from the hourly grain into a daily table, or moving to ClickHouse.
- **Uniques:** visitor-days, not true uniques across a range. True uniques
  would need HLL (the `postgresql-hll` extension or ClickHouse).
- **L2 cache:** a failed `DEL` can leave L2 stale for up to the 1h TTL.
- **Historical uniques:** backfilled values are estimates.
